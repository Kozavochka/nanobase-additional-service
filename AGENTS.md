# AGENTS

Документ фиксирует роли и зоны ответственности ключевых «агентов» системы — самостоятельных сервисов и модулей внутри FastAPI‑приложения `main.py`. Это позволяет быстро понять, какие части кода реагируют на внешний запрос, какие данные им нужны и в каком формате они возвращают результат.

## 1. HTTP Gateway Agent

**Файл:** `main.py`  
**Маршруты:** `/health`, `/predict`, `/alloys`, `/fuel-cells`, `/import-*`, `/process_chart`, `/db-scan-process-chart`, `/colorref-process-chart`, `/evaluate-mask`, `/relation`, `/yolo-axis`, `/yolo-ticks`.

- Реализует FastAPI-приложение и базовую HTTP Basic-аутентификацию (пары логин/пароль берутся из `.env`).  
- Выполняет валидацию входных данных (обязательные поля для инференса, структура JSON-разметки графиков и т.д.).  
- Делегирует работу специализированным агентам ниже и агрегирует их ответы в HTTP-ответы.

## 2. Inference Agent (ModelWrapper)

**Файл:** `main.py` (`ModelWrapper`)  
**Модель:** `LNCF_ETR_model.pickle`

- Подгружает сериализованные `model` и `scaler`, умеет делать предсказания в исходном и лог-масштабе.  
- Ожидает от клиента `x_Co`, `x_Fe`, `Po2`, `T`, `T_sint`. Преобразует их в инженерные признаки (`log_Po2`, `1000/T`, `1000/T_sint`).  
- Возвращает одновременно `log(sigma)` и `sigma`, чтобы фронтенд мог выбрать удобную форму.

## 3. Data Access Agents

### 3.1 Postgres Reader

**Файл:** `pg_connector.py`

- Поддерживает три запроса к БД: `get_all_aloys_json`, `get_all_fuel_cells_json`, `get_all_composites_json`.  
- Использует SSL-соединение и переменные среды `PG_*`.  
- Отдает списки словарей, готовые для JSON-сериализации или дальнейшей отправки в очередь.

### 3.2 RabbitMQ Publisher

**Файл:** `rabbit_client.py`

- Функция `send_message(queue_name, payload)` устанавливает соединение с RabbitMQ и публикует сообщение с `delivery_mode=2` (персистентность).  
- Используется маршрутами `/import-alloys`, `/import-fuel-cells`, `/import-all`, где данные читаются из Postgres и пачками (по 10 элементов) отдаются в очереди `alloys`, `fuel_cells`, `composite`.

## 4. Object Storage Agent

**Файл:** `s3_service.py`

- Инкапсулирует работу с S3-совместимым хранилищем (доступ и конфиг из `config.py`).  
- Предоставляет методы загрузки/выгрузки бинарных объектов и генерации presigned URL, что позволяет остальным агентам работать только с ключами.  
- Используется всеми графическими и файловыми сервисами (Chart, ColorRef, Mask).

## 5. Chart Digitizer Agent

**Файлы:** `chart_processor.py`, `calibration_service.py`

**Состав:**
1. `ROI`, `AxisConfig`, `PlotCalibrator` — описывают прямоугольник интереса и масштабирование пиксельных координат в физические значения. Поддерживаются линейные и логарифмические шкалы, «прилипание» к заданным тикам.
2. `ChartProcessorService` — отвечает за полный цикл обработки графика:
   - скачивает изображение из S3;
   - читает разметку ChartReader (`parse_chartreader_json`) и отбрасывает точки ниже `min_score`;
   - рисует оверлей с найденными точками и загружает результат в `processed/annotated_*`;
   - конвертирует точки в значения осей и выгружает Excel (`processed/values_*.xlsx`).

**Расширения:**
- `/db-scan-process-chart` применяет `DBSCAN` и цветовые кластеризации (`cluster_points_by_color`) для группировки точек, строит отдельную визуализацию и Excel по каждому кластеру.
- В ColorRef-пайплайне (см. ниже) переиспользуется часть логики `ChartProcessorService`.

## 6. Color Reference Agent

**Файл:** `colorref_service.py`

- Принимает список эталонных цветов (`refs` с именем и RGB) и сопоставляет реальным точкам на графике.  
- Может работать как с уже загруженными изображениями (`image_path` в S3), так и с файлом, полученным через `UploadFile`.  
- Ставит локальную копию изображения, пытается построить `PlotCalibrator` (если пришли данные калибровки), затем через `ChartProcessorService.process_colorrefs` определяет кластеры, генерирует визуализацию и Excel с координатами и значениями.  
- Возвращает URL обработанных файлов в `processed/colorref_*`.

## 7. Mask Cleanup Agent

**Файл:** `mask_service.py`

- Скачивает исходное изображение графика и бинарную маску, вычитает маску и выполняет `cv2.inpaint` для восстановления области графика.  
- Загружает очищенное изображение в `mask/graph_clean_*.png` и возвращает путь клиенту.  
- Используется эндпоинтом `/evaluate-mask` и может быть встроен в более длинные пайплайны очистки графиков перед распознаванием.

## 8. Property Relation Agent

**Файл:** `property_relation_service.py`

- Нормализует два набора экспериментальных данных A(T) и B(T), строит общую сетку температур и интерполирует `A(B)` в кубическом (`CubicSpline`) или линейном (`interp1d`) режиме.  
- `/relation` получает массивы температур и значений, метод (`cubic|linear`) и возвращает табличный результат `[{B, A}, ...]` для визуализации или дальнейших расчетов.  
- Может печатать формулы сплайнов (методы `print_formula`, `get_table`) — полезно для диагностики.

## 9. YOLO Axis/Ticks Agent

**Файл:** `yolo_service.py`

- `YoloAxisService` использует pose‑модель YOLO для извлечения 3 ключевых точек: `origin`, `x_end`, `y_end`.  
- `YoloTicksService` использует detect‑модель YOLO, OCR (Tesseract) и дедупликацию, чтобы получить значения тиков по X/Y и вычислить `origin`, `x_end`, `y_end` в координатах графика.  
- `main.py` отдаёт результаты через `/yolo-axis` и `/yolo-ticks`, принимая `image_path` (ключ в S3) и опциональные параметры порогов/классов/модели.

## 10. Supporting Utilities

- `chunked` в `main.py` — помогает делить большие массивы на куски перед отправкой в очередь.  
- `safe_ticks` — защищает от некорректных шагов сетки при построении подписей.  
- `default_serializer` — унифицирует сериализацию дат при отправке данных в RabbitMQ.  
- `.env` + `config.py` — единый источник конфигурации для всех агентов (Postgres, RabbitMQ, AWS/S3, Basic Auth).

## 11. Типовые сценарии

1. **Прогноз проводимости:** клиент вызывает `/predict`, проходит Basic Auth → HTTP Gateway валидирует JSON → Inference Agent трансформирует данные и возвращает `log(sigma)`/`sigma`.  
2. **Импорт справочников:** `/import-alloys` → Gateway читает Postgres → делит пачками → RabbitMQ Publisher уносит данные в очередь → downstream-сервисы подписываются на очереди.  
3. **Оцифровка графика:** `/process_chart` → Gateway собирает `ROI` и оси → Chart Digitizer скачивает изображение, накладывает точки, формирует Excel → S3 Service сохраняет файлы → клиент получает URL.  
4. **Раскраска по эталонам:** `/colorref-process-chart` → Color Reference Agent сопоставляет точки с заданными цветами → выдаёт изображение с подсветкой и таблицу координат.  
5. **Очистка графика по маске:** `/evaluate-mask` → Mask Agent стягивает изображение+маску из S3, очищает артефакты → результат кладёт в S3 и отдаёт ссылку.  
6. **Построение отношения свойств:** `/relation` → Property Relation Agent проводит интерполяцию и возвращает дискретную таблицу A(B).
7. **Автоматическое распознавание осей/тиков:** `/yolo-axis`/`/yolo-ticks` → YOLO Agent возвращает пиксельные точки осей и числовые значения границ.

Эта карта агентов поможет быстрее разобраться в проекте, распределить ответственность между командами и локализовать нужный модуль при изменениях или отладке.
